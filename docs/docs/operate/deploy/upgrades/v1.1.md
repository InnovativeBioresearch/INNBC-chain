This page describes the current INNBC node upgrade process.

The current INNBC deployment model uses the nodeclient bundle and systemd-managed validator services. It does not use the removed legacy bridge, rootchain, SupernetManager, StakeManager, checkpoint, or child-token upgrade flow.

## Build the updated nodeclient bundle

From the repository root:

```bash
go build -buildvcs=false .
make nodeclient
```

The updated bundle is created at:

```text
dist/innbc-nodeclient
```

## Install the updated binary and templates

On the server, run the installer from the bundle:

```bash
sudo ./dist/innbc-nodeclient/scripts/install.sh
```

The installer updates:

```text
/usr/local/bin/innbc-chain
/etc/innbc/node.example.yaml
/etc/systemd/system/innbc-node@.service
```

If `/etc/innbc/genesis.json` already exists, the installer preserves it.

The installer does not create, delete, or overwrite validator key folders under:

```text
/var/lib/innbc
```

## Restart validator services

Restart a single node:

```bash
sudo innbc-chain node restart node1
```

Restart all configured node services:

```bash
sudo innbc-chain node restart all
```

## Check node status

```bash
sudo innbc-chain node status all
```

You can also check systemd directly:

```bash
sudo systemctl status innbc-node@node1 --no-pager
```

## Start and stop nodes

Start a node and enable boot startup:

```bash
sudo innbc-chain node start node1
```

Stop a node without disabling boot startup:

```bash
sudo innbc-chain node stop node1
```

Stop a node and disable boot startup:

```bash
sudo innbc-chain node disable node1
```

## Genesis Changes

Do not replace `/etc/innbc/genesis.json` on a running production chain unless the upgrade explicitly requires a coordinated genesis or fork configuration change.

For ordinary binary updates, update the binary and restart the services. Validator identity folders and existing chain data are preserved.
